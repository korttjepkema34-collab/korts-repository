# Studio authority — start here

Owner-approved version 0.2, published 2026-09-09. These documents govern the cloud-led assistant and supersede conflicting legacy autonomy guidance. Implementation gaps remain explicit; approval of policy does not implement it.

1. [Studio Charter](STUDIO-CHARTER.md): authority, autonomy, privacy and approval boundaries.
2. [Work and Review](WORK-AND-REVIEW.md): investigation, tests, independent review and bounded repair.
3. [Specialist Profiles](SPECIALIST-PROFILES.md): personality, skills, tools and scoped responsibilities.
4. [Kort’s Mailbox](KORTS-MAILBOX.md): durable decisions and safe task resumption.
5. [Obsidian and GitHub](OBSIDIAN-AND-GITHUB.md): knowledge ownership, promotion, navigation and revision handling.

Two repair rounds are the approved design default, not an assertion that the existing controller enforces this exact rule. No time/call cap, provider access or new tool permission is inferred. Personality defaults do not overwrite active private profiles automatically.
